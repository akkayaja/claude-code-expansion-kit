## 💡 새 개념

- **게임 = 입력 → 상태 변화 → 화면 갱신**: 키를 누르면(입력) 점수·위치가 바뀌고(상태 변화) 그걸 다시 그린다(화면 갱신). 1초에 약 60번 반복한다
- **상태(state) = 게임의 세이브 데이터**: 점수, 에너지, 남은 시간, 내 위치, 떨어지는 물건 목록, 게임 단계(시작 전 → 진행 중 → 끝). 화면 그리는 코드는 상태를 **보기만** 하고 바꾸지 않는다
- **기획서를 먼저 쓰면 코드가 쉬워진다**: 기획서의 '상태 표'가 그대로 코드의 `state`가 됐다
- **난이도는 숫자다**: "너무 쉬워"를 속도 배수·나오는 간격·야근 비율 세 숫자로 바꿔서 해결했다. 직접 해 보고(미션 3) 고치는(미션 4) 순서가 중요하다
- **localStorage = 브라우저의 작은 메모장**: 최고 점수를 여기에 적어서 새로고침해도 남는다. 단, **각자 브라우저에만** 저장돼서 친구 기록은 내 화면에 안 보인다. 모두가 보는 순위표를 만들려면 서버·DB가 필요하다
- **GitHub Pages = 내 저장소의 진열장 칸을 쇼윈도로 열기**: `docs` 폴더를 사이트로 보여 주게 설정하면 push할 때마다 자동으로 반영된다. Vercel처럼 따로 가입할 필요가 없었다
- **Web Audio = 코드로 연주하는 악기**: "몇 Hz에서 몇 Hz로, 몇 초 동안"을 정하면 소리가 만들어진다. 녹음 파일이 없어서 저작권 걱정이 없다. 브라우저는 사용자가 **처음 누른 뒤에만** 소리를 허락한다
- **리듬 = 16칸 박자표**: 한 마디를 16칸으로 나누고 칸마다 쿵·착·치를 정한다. 베이스를 엇박에 두면 리듬감이 생긴다
- **`cd -` = 바로 전 폴더로 돌아가기**: `cd ../..`로 홈 폴더까지 올라가 버렸을 때 한글을 안 치고 돌아왔다. 이미 들어온 폴더에서 `cd 12*`를 다시 치면 "no matches found"가 나오지만 위치는 그대로다

## 📝 포트폴리오 한 줄

- **문제:** 아이디어는 있어도 게임처럼 '상태가 계속 바뀌는' 프로그램을 만들어 본 적이 없었고, 만든 걸 남에게 보여 줄 방법도 몰랐다
- **해결:** 기획서로 규칙과 상태를 먼저 정한 뒤 HTML 파일 하나로 "퇴근 버스 잡기"를 만들었다. 직접 5판 해 보고 너무 쉬워서 15초마다 빨라지는 4단계와 최고 점수 저장을 넣었고, 휴대폰 터치와 코드로 만든 효과음·배경음을 더해 GitHub Pages로 공개했다
- **효과:** 설치 없이 링크 하나로 컴퓨터와 휴대폰에서 바로 할 수 있는 게임이 생겼다 (v1 → v3, 음원 파일 0개)
