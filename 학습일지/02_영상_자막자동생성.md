## 💡 새 개념

- **음성 인식 = 게임기 + 게임 칩**: whisper-cli는 프로그램(게임기), 모델 파일은 AI의 뇌(게임 칩). 칩만 바꿔 끼우면 크기별로 시험할 수 있다
- **SRT 자막**: 번호 → 시간 → 대사 → 빈 줄이 반복되는 단순한 글자 파일. 메모장으로도 고칠 수 있다
- **모델이 크다고 무조건 좋은 건 아니다**: 이 영상에서는 small이 large와 정확도가 같은데 3.6배 빨랐다. base는 "행은"을 "행운"으로 적는 식으로 비슷한 소리를 헷갈렸다
- **AI가 모두 틀린 곳은 사람이 본다**: 세 모델 모두 `안의`를 `안에`로 들었다. 소리가 같은 말은 크기와 상관없이 확인해야 한다
- **자막 트랙과 번인**: 자막 트랙은 DVD 자막(켜고 끄기 가능), 번인은 영화관 자막(그림에 박힘, 쇼츠·인스타용)
- **파일을 못 찾으면 `pwd`부터**: 한 칸 위 폴더에서 명령을 실행해 "not found"가 났다. 내 위치부터 확인하기
- **바로가기(심볼릭 링크)**: 73B짜리 `ggml-large-v3.bin`은 화살표(`->`)로 진짜 2.9GB 파일을 가리키는 바로가기였다

## 📝 포트폴리오 한 줄

- **문제:** 영상 자막을 손으로 달면 영상 길이의 5~10배 시간이 든다
- **해결:** 무료 음성 인식(whisper.cpp)으로 39초 강의의 한국어 자막을 10초 만에 만들고, 정답과 비교해 1곳만 고친 뒤 자막 트랙과 번인 영상 두 가지로 만들었다
- **효과:** 정확도 99.5%, 사람이 고친 글자 1곳. 모델 3개를 비교해 "짧은 영상은 large, 긴 영상은 small"이라는 선택 기준을 얻었다

## 💬 느낀 점 (Claude가 대신 작성, 내가 확인)

- 39초 영상을 10초 만에 받아 적고 틀린 글자가 하나뿐이라 놀랐다. 그래도 세 모델이 모두 같은 곳을 틀린 걸 보니, 마지막 확인은 사람이 해야 한다는 걸 알았다.
- "not found"나 "덮어쓸까요?"처럼 길을 잃은 순간이 있었지만, 내 위치(`pwd`)와 명령 순서를 확인하는 습관이 생겼다.
