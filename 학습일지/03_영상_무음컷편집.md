## 💡 새 개념

- **silencedetect = 방음 측정기**: "-30dB보다 작은 소리가 1초 넘게 이어지면 무음"이라는 기준을 내가 정한다. 기준이 바뀌면 결과도 바뀐다
- **기계는 무음 시작을 항상 조금 빨리 잡는다**: 말소리는 서서히 작아지기 때문. 그리고 1초 기준이라 맨 앞 0.6초 무음은 일부러 안 잡혔다
- **trim + concat = 가위와 테이프**: 남길 구간을 오려서 이어 붙인다. 처음 쓴 `select` 방식은 ffmpeg 8.0에서 화면만 잘리고 소리는 안 잘렸다 → 결과는 꼭 화면·소리 길이를 둘 다 확인
- **0.3초 여유**: 완전히 붙이면 말이 쫓기듯 들린다. 문장 사이에 0.6초 숨 쉴 틈이 생겨 자연스러워진다
- **for 반복문 = 바구니째 세탁**: `for f in 폴더/*.mp4; do …; done` 한 줄로 영상이 3개든 300개든 같은 기준으로 처리한다
- **같은 입력 → 같은 결과**: 반복문을 두 번 돌려도 숫자가 똑같았다. 자동화 도구는 믿을 수 있어야 한다
- **Claude에게 잘 요청하는 법**: "어떤 파일을 / 무엇을 / 원본은 어떻게 / 어떻게 확인할지" 4가지를 말한다. 도구 이름을 몰라도 **성공 기준**("화면과 소리가 둘 다 잘렸는지 확인해 줘")을 말하면 실수를 잡을 수 있다
- **CLAUDE.md = 업무 수첩**: 자주 쓰는 도구를 적어 두면, 말하지 않아도 Claude가 알아서 그 도구를 쓴다
- **터미널 표시가 깨져도 결과는 정상일 수 있다**: 한글 경로가 `여 러영상`처럼 보였지만 파일은 제대로 생겼다. `ls`로 직접 확인하기

## 📝 포트폴리오 한 줄

- **문제:** 영상 편집에서 말 사이의 쉬는 구간을 손으로 찾아 자르는 일이 가장 지루하고 오래 걸린다
- **해결:** ffmpeg의 무음 탐지로 구간을 자동으로 찾고, 파이썬 스크립트로 잘라 붙인 뒤, 반복문으로 여러 영상을 한 번에 처리했다
- **효과:** 33.5초 영상을 27.8% 줄였다(0.3초 여유). 무음 탐지 정확도는 정답 대비 최대 0.09초 차이였고, 명령 한 줄로 여러 영상을 같은 기준으로 편집할 수 있게 됐다

## 💬 느낀 점 (Claude가 대신 작성, 내가 확인)

- 영상의 3분의 1 이상이 "쉬는 시간"이었다는 게 놀라웠다. 그걸 명령 한 줄로 찾고 잘라 내니 편집 시간이 확 줄 것 같다.
- 도구 이름을 몰라도 "이렇게 되면 성공"이라고 말하면 된다는 걸 배웠다. 실제 유튜브 편집에 쓸 때는 배경음악을 넣기 전에 무음 컷부터 하고, 목록을 먼저 확인하는 습관을 들이고 싶다.
